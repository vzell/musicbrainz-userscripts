## 9.97.32 — 2026-02-28

## 9.97.31 — 2026-02-27

**🐛 Bug Fixes**

- Fix ghost sidebar toggle handle: The sidebar toggle handle is now positioned dynamically via JS (updateHandlePosition) instead of relying on a hard-coded CSS 'right: 240px'. The root cause was that toggleAutoResizeColumns changes the sidebar from its default right-floated layout to 'position: sticky; left: 0', making the sidebar appear at the LEFT viewport edge during horizontal scrolling — so the fixed handle at 'right: 240px' ended up floating over the content area rather than being adjacent to the sidebar. updateHandlePosition() reads the sidebar's live getBoundingClientRect() on every scroll, resize, and toggle event and sets handle.style.right = (window.innerWidth - sidebar.left) px, keeping the handle flush against the sidebar's actual rendered left boundary at all times regardless of scroll position or CSS position changes. The CSS 'transition: right 0.3s ease' and the '.handle-collapsed { right: 0 !important }' rule have been removed to avoid CSS/JS fights on high-frequency scroll events.


## 9.97.30 — 2026-02-27

**✨ Enhancements**

- Global filter: the 'sa\_filter\_focus\_prefix' (default '🔍 ') is now permanently visible in the global filter field at all times — focused or not, empty or not. The field is initialized with the prefix on creation and every programmatic reset (fresh fetch, disk load, clear-all, ✕ button) restores it to prefix-only rather than to an empty string. This is different from column filter inputs, where the prefix appears only while the field has focus. All values read from the global filter field pass through stripFilterPrefix() before use, so the invariant is transparent to all filtering logic.

**♻️ Refactoring**

- The focus and blur event listeners on the global filter input have been removed. The blur listener's secondary responsibility (calling runFilter() after stripping the prefix) is no longer needed because the prefix is never stripped on blur. The keydown guard (guardFilterPrefixKeydown) and the prefix-safety-net inside the input listener remain.

## 9.97.28 — 2026-02-27

**🐛 Bug Fixes**

- Load from Disk — RegExp pre-filter now correctly applied: when the 'Regular Expression' checkbox in the Load dialog was checked, no rows were loaded at all. Root cause: confirmLoad() tried to sync the regex flag to the live filter bar by writing to 'preFilterRegexLabel.querySelector("input")' — but 'preFilterRegexLabel' was never declared anywhere in the script, so the typeof guard suppressed the write and 'preFilterRxCheckbox.checked' stayed false. The button tooltip now dynamically displays the currently configured shortcut key.

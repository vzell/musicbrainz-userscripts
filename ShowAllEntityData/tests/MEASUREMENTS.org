#+TITLE: Measurement log
#+STARTUP: showall

Every timing, wall clock and count this project has measured, with the machine
it was measured on.

*Why this file exists.* Timings were previously scattered across
=PERFORMANCE.org=, =DEBUG-NOTES.md=, commit messages and the
=interaction-perf-*.json= arms, and none of them recorded the HOST. That gap
cost real work: two =main= captures three script versions apart came out 1.5-2x
different, and because nothing said which machine either ran on, the difference
was attributed first to machine state and then to concurrent load — both
guesses, and the second was disproved. A number with no machine attached cannot
be compared to a later one, so it is not evidence, it is decoration.

*Rules for adding a row.*

- *Record the hostname AND the time*, from the run itself and not from memory.
  =capture-interaction-perf.js= and =capture-snapshots.js= write a =machine=
  block plus =startedAt=/=finishedAt= (UTC) into their JSON; copy from there.
  The time is not ceremony — "was MusicBrainz busy at that hour" is a real
  hypothesis about any live-page number, and it can only be tested against runs
  that recorded when they happened. It has been tested once, below, and came
  back negative; that answer is only available because the times were
  recoverable from commit timestamps.
- *Say what the measurement was PROBING*, not just which command produced it.
  "Sort click to settled status text" is a measurement; "sort" is a label.
- *Name the page*: pageType, its =tableMode= (single/multi) and its human page
  title, the same four columns =tests/snapshots/registry.org= uses. A bare URL
  or a bare =rendered.html= is unreadable a month later.
- *Mark an unknown host as unknown.* Do not infer it. Rows below that predate
  machine recording say so, and one of them is known to be from a DIFFERENT
  machine.

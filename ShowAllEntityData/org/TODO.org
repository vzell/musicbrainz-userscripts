** summary

ShowAllEntityData is not what removes the column. MusicBrainz's own React code does, so how it turns out depends on timing. That's why your re-check with SAED active worked.

**What happens:** the tracklist arrives as server-rendered HTML, and React then "hydrates" it (attaches to the existing markup) in a `DOMContentLoaded` handler.
- **Nuclear Tags runs after hydration:** its checkbox column stays.
- **Nuclear Tags runs before hydration:** the extra cells no longer match what React expects. React throws error #418,
  empties `div.tracklist-and-credits`, and renders the tracklist again without the column. Nuclear Tags' observer does
  fire on that re-render, but its "already injected" check only looks at the sidebar form, so it never adds the column
  back.

**Why it came and went for you:** when Tampermonkey runs Nuclear Tags relative to that handler varies from load to
load. It depends on cache state, network speed, and how many other scripts Tampermonkey has to inject; SAED alone is
about 85k lines. Disabling SAED changed the timing, so it looked like SAED was the cause. Your later reload with all
three active happened to land on the good side of the race.

**Evidence:** a new probe, `scripts/probe-nuclear-tags-column-loss.js`, loads the release page live and logged in, and logs the stack trace of anything that removes a checkbox cell.
- With no userscripts, React hydrates without any error.
- With Nuclear Tags, the 43 cells are added at about 290 ms. At about 460 ms React throws #418 and clears the tracklist, and the stack points into MusicBrainz's own scripts.
- The same happens with INLINE STUFF and/or SAED added, and neither appears in the trace.
- The test harness injects scripts earlier than Tampermonkey does, so there the column is lost on every run.

So my earlier "Nuclear Tags needs no change" was right for the ISRC bug but wrong for this one. There are now two separate fixes:

| Bug                                       | Script to fix | Files in `debug/`                                                                            |
| ----------------------------------------- | ------------- | -------------------------------------------------------------------------------------------- |
| ISRC/AcoustID land in the checkbox column | INLINE STUFF  | `mb_INLINE-STUFF.user.js`, `mb_INLINE-STUFF-title-cell.patch`                                |
| Checkbox column vanishes                  | Nuclear Tags  | `MusicBrainz Nuclear Tags.user.js`, `MusicBrainz-Nuclear-Tags-restore-checkbox-column.patch` |

The Nuclear Tags fix makes the column-adding function safe to run repeatedly: it only adds missing cells. The script's
existing observer now calls it again on release pages, so the column comes back if React removes it. It can't touch
SAED's own tables, because SAED removes the `medium` class from them. React still logs #418, because the fix restores
the column instead of preventing React's rebuild; there's no reliable "hydration finished" signal to wait for.

The TTL could not be raised on its own: a 503 from coverartarchive.org was being

2.) *No umbrella =503= branch.* =main= is the trunk; one short-lived branch per
sub-step, off =main=, live-tested, merged back. Reasons, in order of weight:

- The eight items in =org/503-handling.org= are independently shippable. The one
  real dependency (item 1, the shared transient classifier, feeding items 3-4 and
  6) is a *sequence on main*, not a batch that must integrate first.
- Two levels break the WIP-changelog rule: =scripts/fold-wip-changelog.py= is
  one-level (branch → =main=) and deletes the WIP file when it folds, so entries
  would pile up on =503= until one final fold — the whole batch shipping as a
  single version block, which is the opposite of (c).
- (c) is the tell: if most sub-steps go straight to =main= anyway, =503= spends
  its life being back-merged, conflicting every time in =// @version=,
  =ShowAllEntityData_CHANGELOG.json= and =org/503-handling.org=.

*Worktrees: not per sub-step.* The script is re-imported into Tampermonkey by
hand, so a branch switch in the main checkout costs the same and skips
=npm install= plus a fresh =npm run auth:login= (=playwright/.auth/= is
gitignored, so a new worktree runs live specs *logged out*, silently). Keep a
worktree for the one case the project's rules demand it: a perf A/B, where
=main= and the branch must be measured in one session on one host.

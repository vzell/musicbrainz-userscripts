Hi @majkinetor,

one more interop point, small: String Theory's idle mode over a SAED table.

With String Theory's defaults (idle on, 5 minutes, theme and effect "Random"), reading a long SAED table without
touching the mouse for 5 minutes is enough: the page cross-fades to a random theme, and Event Horizon's effect (the
hex grid here) is drawn over the whole page, table included. SAED's own colours are fixed, so they no longer fit the
theme around them, and every 5 minutes it changes again ("continuous"). It also costs a little: with an effect
running, rendering 2,146 rows took 2.98 s instead of 2.57 s (median of three runs each); fetching was not affected.

[screenshot]

A request, using the convention we already have: could `beginIdle()` (`themes/runtime.js`) wait while
`<html data-mbu-quiet>` is set? SAED already sets that mark while one of its tables is shown on MusicBrainz's page
(C4, the corner launchers). Something like:

```js
function beginIdle() {
  if (document.documentElement.hasAttribute('data-mbu-quiet')) {
    idleTimer = setTimeout(beginIdle, read().idle.minutes * 60000);
    return;
  }
  // ... as now
}
```

That keeps idle mode exactly as it is everywhere else, and it starts again by itself once the mark is gone
(Event Horizon's view shown, or the table left). Since `data-st-eh-fx-idle` comes from String Theory, Event
Horizon's idle effects would wait too, without a change there.

One thing to know: SAED ties the mark to its setting "Hide String Theory's corner launchers" and to its menu row
"Show corner launchers". A user who brings the launchers back gets idle mode back too. If you'd rather keep "quiet"
meaning only the corner, a separate mark is fine with me, e.g. `data-mbu-idle-off="saed"` (value = owner, as with
the others), and I'll set that one instead.

Thanks!

** What the probes established

| PT           | Detail URL                    | Framing headers        | Charset                        | Page size |
|--------------+-------------------------------+------------------------+--------------------------------+-----------|
| =sl-*=       | =?item=N&category=C=          | none                   | UTF-8                          | ~40 KB    |
| =jl-list=    | =/html/YYYYMMDD[_N].htm=      | none                   | windows-1252, no declaration   | ~1.6 KB   |
| =bs-records= | =detrec.aspx?code=X=          | none                   | UTF-8 (the meta tag is wrong)  | 5–8 KB    |
| =bb-songs=   | =/song:<slug>=                | =X-Frame-Options: SAMEORIGIN= | UTF-8                   | 65–115 KB |

- *The detail pages match no =@include=*, so the script never runs on them.
  All data has to be fetched and parsed from the list page.
- *Every detail page has the same origin as its list.* Plain =fetch= works, including through
  CloudFlare on springsteenlyrics.com. A same-origin iframe also works, and
  the list page can restyle its =contentDocument=.
- =fetchHtml()= decodes with =res.text()=, which is UTF-8 only. jungleland.it
  needs =arrayBuffer()= + =new TextDecoder('windows-1252')=.

*** Where the data sits

- *sl*: inside =.project-detail=. The header fields are =<span class="text-primary"><em>Label:</em></span> value<br>=, the
  version follows =glyphicon-option-vertical=, and the tracklist is the first =span.monospaced=.
  Scans are =img[src$="_tn.jpg"]=.
- *jl*: =<a>Title: …</a>=, =<a>Date: …</a>=, =<a>Uploader: …</a>=. Images are
  =..\artwork\<decade>\thumb\tn_<stem>_<label>.jpg=, with *backslashes*.
- *bs*: =Title  : <b>…</b><br>Support: <b>…</b><br>…=, then =Notes:<br>…</p>=,
  then a =<table>= with columns Pos / Title / From / Notes / Ver. The labels
  differ by record type (Matrix/Producer/Vinyl vs Catalogue number/Pressed
  in/Release period), so read them as a generic label map.
- *bb*: =#page-title=; =Track N of <em>Album</em>, YYYY.=; =Performed live
  <strong>N</strong> times (=; the first =a[href^="/gig:"]= is the newest
  show; =<p>Released on …</p>= with =a[href^="/retail:"]= plus =(YYYY)=.

** Parser findings (prototype run, 2026-10-07)

- sl 1331 and 1332: an *unnumbered* tracklist directly after Duration, with no
  =<br>= between them, so a naive Duration read swallows the songs. The parser
  must cut Duration at the first newline and fall back to plain lines, and say
  so in the UI.
- sl 2045: a numbered tracklist with no "Disc N:" header. Treat it as one disc.
- bs: the From column repeats a source as =&nbsp;&nbsp;"= ("same as above");
  each one has to be filled from the row above. Song and show links are
  =href="#"=, so there is nothing to link to.
- jl: thumbnails can be predicted from the file name for front and back, but
  the extra scans and the uploader need the page.
- bb: the page is large; cache only the extracted fields. The tour breakdown
  ("Performed at N show(s) of M on the … Tour") sits inside nested markup that
  a simple regex missed; it needs a DOM read.

** Options (all mocked in [[file:detail-pages-mockups.html]])

They all share one foundation:
- =DetailPageParsers[site]= returns ={title, fields[], tracks[], images[], notes[]}=;
- a same-origin detail fetch with a 1.1 s gate modelled on
  =_relAwaitRateSlot=, with per-host decoding;
- an IndexedDB store =detail-pages= keyed by URL, with a TTL. That means
  bumping =_ART_IDB_VERSION= in =_artOpenIdb()=. IndexedDB is per origin, so
  each host gets its own empty database.

| # | Option            | Reuses                                                                               | Verdict  |
|---+-------------------+--------------------------------------------------------------------------------------+----------|
| A | Hover peek card   | =data-mbtt-fn="detail"= in =_mbttResolve()= / =_mbttAfterShow()=; =_OTHER_RICH_TIPS= | phase 1  |
| B | Pinned preview    | =createInfoDialog()= (geoKey, Esc, click-outside); Extracted / Live-page iframe      | phase 1  |
| C | Side drawer       | =#mb-art-viewer= key-capture pattern                                                 | optional |
| D | Detail columns    | Relationships deferred-column pattern + the four post-render duties                  | phase 2  |
| E | Inline expand row | –                                                                                    | avoid    |

- A needs one addition to =_initStatTooltip()=: Esc hides the card. Today
  only =mouseout=/=mousedown= do. Space (or a 🔍 after the link) pins the card
  into B. On touch, the 🔍 is the only way in.
- D: a fixed column group emitted by each converter (=_slBuildRow=,
  =_bsBuildRow=, …), not via =injectedColumns=, which is wired to WS/2.
  Cells always exist; only their content is deferred. Write to the master
  rows; after every write clear the 📊 cache, =_filterResultCache= and
  =_rowTextCache= on the source row, then re-run =runFilter()=. Name the header
  toggle something other than =.mb-caa-col-hdr-btn= or
  =.mb-col-collapse-hdr-btn=, because =initCollapsableColumns()= removes both.
- E breaks =sortLargeArray()= ordering, =renderGroupedTable()= cloning, row
  counts and the column indexes. Its safe version is D's tracklist cell as a
  multi-row =ul>li= with the existing ▶ collapse.

*** Cost of D at 1.1 s per page

| Table                 | Rows  | Full load  |
|-----------------------+-------+------------|
| sl-bootlegs, one page | 100   | 1 min 50 s |
| bs-records unofficial | 1,878 | 34 min     |
| bs-records official   | 1,186 | 22 min     |
| bb-songs              | 1,679 | 31 min     |
| jl-list               | 5,839 | 1 h 47 min |

So D loads on demand, either per table (header toggle) or per cell (click). It
starts collapsed above a threshold, as =sa_rel_collapse_threshold= does, and
anything cached by A or B costs nothing.

** Recommendation

Phase 1 is the foundation plus A and B, behind a per-site setting that is off
by default and nested under the site's existing =sa_enable_<site>= gate. It
adds nothing to the filter/sort/render path and changes nothing on
MusicBrainz (host-gated). Phase 2 is D, reusing phase 1's parsers and cache.
Build C only if B feels cramped in practice.

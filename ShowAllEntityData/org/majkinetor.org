*** Method — clone or read from GitHub? (3.)

*Clone.* The toolset is ≈16 MB of JavaScript in 15 single-file scripts: EH alone is 1.07 MB / 11,160 lines,
Apollo 1.5 MB, and the ST bundle 7.4 MB. WebFetch summarises and truncates, so it cannot answer "which function
does X". A local clone can be grepped and pinned to a SHA, and the live-interop harness needs the files locally
anyway.

#+begin_src sh
git clone --depth 1 --filter=blob:limit=1m --sparse https://github.com/majkinetor/musicbrainz-userscripts debug/majkinetor
git -C debug/majkinetor sparse-checkout set --no-cone '/*' '!*.png' '!*.jpg' '!*.gif' '!*.webp' '!*.mp4'
git -C debug/majkinetor pull            # follow upstream later; re-pin the SHA below
#+end_src

- Pinned: =326c6a4= (2026-11-06T11:12:03+01:00, "RG lookup only for an enabled Discogs, once per session (#931)").
- =debug/= is gitignored; the clone is 140 MB without images.
- The code is untrusted: it is only read and grepped, never run with node/npm from inside the clone.
- For the live probe, =event_horizon.user.js= and =string_theory.user.js= were copied into
  =tests/fixtures/live-userscripts/= (gitignored, registered in =manifest.json=).

  porting *ideas* and data tables (role maps) is the safer route.

*** Shared runtime (all scripts)

**** Request gate — =dev/net/mb-gate.mjs=, inlined as ST-NET (EH:58-244)

- *State*: cross-tab, in localStorage =mbu:mb-gate= ={tat, cool, hot, lead, leadUntil}=, read-modify-written under a
  Web Lock =navigator.locks.request('mbu-mb-gate')= (3 s abort, unlocked fallback). Only =/ws/2= is gated (=mbnGated=).
- *Pacing*: GCRA-style, =MBN_GAP=1000= ms. Background requests may burst to =MBN_BURST=3=; foreground requests book at
  once. A slot is reserved first, then waited for in 250 ms slices so cancellation is prompt (=mbnSlot= ≈94).
- *Lead*: =mbnLead(token, ms)= (≈126), capped at 10 s. The tab whose page is loading leads, and every other script and
  tab waits. A hidden tab never leads.
- *429/503* (=mbnAnswer= ≈132):
  - honours =Retry-After= (seconds or a date);
  - =hot= rises by one per throttle /episode/ (max 6) and resets after 30 s of quiet;
  - hold = =min(max(1 s, RA) × max(1, hot), 60 s)=, written to the shared =cool=, so *every script in every tab holds*;
  - =mbnFetch= retries up to 4 times.
- *Browser check*: =mbnIsCheck= / =mbnReverify= (≈193-243) pass "Verifying your browser" in a hidden 1×1 same-origin
  iframe, then retry.
- *SAED today*: a per-tab, in-memory slot (=_relAwaitRateSlot=, 1100 ms), =_ws2GetJson= transient retry,
  =_parseRetryAfterMs=. =_mbIsBrowserCheck= only tells the user to open the page.
- *Verdict*: *adopt*. Booking SAED's ws/2 requests in the same =mbu:mb-gate= key makes SAED pace together with all of
  majkinetor's scripts. Also take the lead idea, the per-episode escalation and the iframe re-verify. SAED's main fetch
  is native HTML, which this gate does not cover; ws/2-heavy columns (Relationships, popups, Discogs MB column) are.

**** Corner launchers / dock — =dev/ui/ui-components.mjs= (=mbuDock= UI:794, =mbuDockItem= UI:1082, =mbRestackCorner= UI:1110)

- *Launcher attributes*: =data-mb-corner="br|bl|tr|tl"=, =-order=, =-label=, =-paths= (a regex on the path),

**** Logging — =mbuLog= (UI:1184-1810)

This is most likely what TODO.org:1842 "adapt the logging framework" means.

- *Use*: one logger per script, =LOG = mbuLog({name, version, key, history})=.

**** Viewer mechanics (the part that matters for 4.)

- *Start (EH:11149-11158)*: if =S.on= (*default =true=*, EH:3242 =S= object), it injects =#eh-hide= and calls
  =prefetch(PAGE_ID)= at document-start. =start()= (EH:10819) records =mbBody = document.body=, puts up the
  launcher, then runs =setTimeout(() => setOn(S.on && !off), 0)=. The tick is there so String Theory members can
  read the native page first.
- *=setOn(on)= (EH:10502)*:
  - *on*: =documentElement.insertBefore(ehBody, mbBody); mbBody.hidden = true=. From then on, *=document.body= is
    EH's body*. MB's body stays in the document, hidden (#853).
  - *off*: =ehBody.remove(); mbBody.hidden = false=.
  - Only =:scope > [data-mb-corner]= children move between the bodies.
  - Turning off after navigating inside EH sets =sessionStorage 'eh-off'= and *reloads* the page (EH:10505).
  - The on/off choice is saved (=switchOn= → GM =view.on=), so the next page opens the same way.
- *Navigation*: =pushState= only through =ehPush= (EH:10855); =navTo= (EH:9441) maps a URL to a view;
  =popstate= into something EH can't show, or with EH off, reloads (EH:10498).
- *Marks on =<html>=*: =data-mbu-page= (path + query), =data-mbu-release= (MBID), =data-mbu-dock=; ST adds
  =data-mbu-st=. Scripts that "follow EH" observe these (PC, IS, MC; ST starts members later through
  =data-mbu-page=).
- *Views*:
  - *own view*: home, all 12 entity root pages, tags, aliases, relationships, recordings, works, events,
    artists/labels subpages, user, collections, ratings, tag, search, history and single edits, cover/event art,
    disc IDs, cdtoc;
  - *native page re-styled*: edit-relationships, =/releases=, =/details=, =edit_annotation=, set-cover-art,

Answers to your three questions:

- *Will my action buttons show up and work?* Yes on MB's own page. While EH shows (the default after installing),
  they are present but hidden in MB's body; one V shows them. They are never visible inside EH's views, because
  SAED never puts anything into =#app=.
- *Can we switch back and forth?*
  - On the page the tab loaded: yes, freely (V/V), and the FRP is kept.
  - After moving inside EH: V reloads into the native page *of the page EH shows*; SAED works there; V brings EH
    back.
  - The way back is lossy in one direction only: an FRP is lost when EH navigates elsewhere and you turn EH off
    there, which reloads. Re-pressing the button (or a disk save) restores it.
- *Other pitfalls*:
  1. *Dead hover cards after V* when SAED started under EH (=#mb-stat-tooltip=, and likewise every element SAED
     keeps a reference to and appends once to =document.body=: =#mb-vsb-mask=, the history submenu panel; 59
     =document.body.appendChild= sites in SAED). Fix: append our floating hosts to =document.documentElement=
     (outside both bodies, as the dock does), or re-attach on show (the toolbar-menu pattern), or re-parent them
     when =<html data-mbu-page>= changes.
  2. *EH's bare-letter keys on our FRP* (o/e/r/c/h/t/d/a/s/p/./,) navigate away. Users can turn them off in EH's
     Ctrl+/ palette (=S.keysOn=). On our side: when the FRP is shown, stop those keys in a capture-phase listener
     unless a modifier is held. Or ask majkinetor to skip when =<html>= carries an "app owns the keys" mark.
  3. *Key clashes*:
     - ST's palette takes *Ctrl+K* (SAED's "Show shortcuts help") in the window *capture* phase with
       =stopPropagation= (=palette.js:562-575=), so ours never fires.
     - EH binds *Ctrl+L* to "forward", which is SAED's "Load from disk"; both fire (bubble, same =document=).
     - SAED's typing guard misses =<select>= and contentEditable.
  4. *Request budget*: majkinetor's scripts share one cross-tab gate; SAED isn't in it. On a release page with ST
     (IS, PC, MC, Fusion, Fuzzy Logic and EH all asking ws/2) our Relationships/popups/Discogs MB column add to the
     same per-IP budget, and a 503 makes *them* hold but not us. Fix: book our ws/2 in =mbu:mb-gate=.
  5. *ISRC Scout*: the =data-tip= change (Links platform data lost), its document-wide =.ii-col= wipe and re-add on
     our FRP, and the =#mbu-tip= tooltip stacking with our cards.
  6. *Document-wide observers* from IS, Fuzzy Logic (2), Mammoth and PC run on every SAED re-render.
     Perf: not measured, worth a =run-perf-comparison= arm with the ST bundle.
  7. *State that sticks*: EH remembers on/off per browser; Apollo's toggle is global "on every tab until you switch
     back". A user who switched EH on once has no SAED buttons on any EH page until V.

* Root cause (read from the three =debug/work-ComeTogether-*.html= snapshots, 2026-09-21)

Two independent defects that happen to meet on the same panel.

** Bug A — =" feat. "= missing from "Join phrases"

Row 46 of =debug/work-ComeTogether-final-filtered.html= is literally:

#+begin_src html
<bdi><span class="mp"><a href="/artist/eeb1195b-…" title="Guns N’ Roses (…)">Guns N’ Roses</a></span> feat. <a href="/artist/70248960-…" title="Springsteen, Bruce">Bruce Springsteen</a></bdi>
#+end_src

=_findCellJoinPhrases()= accepted an entity boundary only as a DIRECT CHILD of
the =<bdi>= — a bare =<a>=, or a =span.name-variation= wrapping exactly one.
MusicBrainz's own native =<span class="mp">= open-edits marker is neither, so
that =<bdi>= reported ONE entity, =entityIdx.length < 2= short-circuited, and
the phrase never existed at all: not as a 📊 entry, not for
=_cellMatchesStructureMode()='s =joinphrase:= filter, not for
=_highlightJoinPhraseMatch()=.

The telling detail is that the SAME row's "» artist name: Guns N’ Roses" entry
IS offered (visible in =…-uvd.html=): =_findCellEntityRefs()= resolves its
governing =<bdi>= with =a.closest('bdi')= and walks through =.mp= transparently.
So the two finders disagreed about where an entity boundary is in one cell.

** Bug B — the badge count and the filtered result disagree

With =Artist= typed-filtered to ="bruce"= (7 rows) the panel offers
=(3) » join phrase: with=; checking it yields 9 rows.

A column filter input is architecturally EITHER typed text OR a checkbox value
set: =applyUniqValueSet()= overwrites =input.value= and =getColFilters()=
returns one descriptor shape or the other. =…-uvd-filtered.html= shows the end
state — =data-mb-uniq-values="[&quot;\u0003joinphrase:with&quot;]"= with the
typed ="bruce"= simply gone.

But =openUniqDrop()= collects its counts from the CURRENTLY VISIBLE rows, i.e.
from the typed filter's 7. So the count answers "and" while the filter answers
"instead". The two can only be reconciled by ANDing.

* Fix (branch =fix/uvd-join-phrase-wrappers-and-typed-filter-and=)

- A: =_findCellJoinPhrases()= resolves each qualifying anchor's boundary through
  ANY wrapper — nearest common ancestor inside the =<bdi>=, then each anchor's
  own highest ancestor strictly below it. Subsumes =.mp=, =.name-variation=,
  either nesting order, and a single wrapper enclosing BOTH anchors.
- B: the typed text is stashed on =input.dataset.mbUniqTypedText= when a value
  set is first applied over it; =getColFilters()= emits a SECOND, plain
  descriptor for the same column index, which =testRowMatch()='s existing
  =for (const f of colFilters)= loop ANDs. Unchecking everything restores it.
  Input reads =bruce + » join phrase: with=.
- Deliberate asymmetry, kept: TYPING into a field that already holds a value set
  still drops the value set. The input's text IS the summary label, so editing
  it can only mean editing that string.

Hovering inside the Space window

On the page, resting on a link shows its card and Space pins it into this window. Inside the window, a click already does the right thing, but resting on a link shows nothing: you only find out what a link is by clicking it. Six suggestions below, each a switch on the window as it is today. Images get their own treatment (H4).

Hover a link, todayNothing. The card engine leaves the window out on purpose (_DP_PAGE_SKIP).
Click a MusicBrainz linkOpens it in this window (drill-down), ← Back returns.
Click a Discogs linkEvery link in a Discogs window opens in it too.
Click an imageThe artwork viewer, over the window.

Try it: rest on a link (hold Ctrl for its card), on an image, on ← Back; click; press Space on a card; Esc

Suggestions

Six ways to make a resting pointer useful

H1

What a click does

recommended

The window's foot line says what the hovered thing is and what a click will do: "Opens here: Label · Columbia", "New tab: musicbrainz.org/…", "Viewer: Back · image 2 of 8". Like a browser's status bar, but in words. With nothing hovered it shows the window's keys.

Cost
None: read from the link and the record already shown.
Rules
Keyboard focus counts as hover (Tab through the links).
H2

Marked links

recommended

Before any hover, a link that opens here has a dotted underline, one that leaves the page ↗, an image a ring and a zoom pointer. A link whose record is already read has a small green dot (with H5).

Cost
CSS only.
Rules
Classes set when the window's HTML is built, never in a table.
H3

Card in the window

recommended

A link that opens here gets the same card as on the page, beside the link, above the window: from memory when it was read before, "Loading…" otherwise. Space on it opens it here, like a click; on the page Space pins a card into the window, so the key means the same thing.

Cost
The page's rule: a MusicBrainz record is asked through the rate gate, wanted only while the card shows; a host never reached is first asked on Space, never on a hover.
Rules
Ctrl as on the page (setting "card without Ctrl"); Esc closes the card first.
H4

Image preview

recommended

Images are not links to read: resting on one shows it large, with its type, its place in the set and "Click: viewer". Shift shows it larger. The cover too.

Cost
One image (the 500 / 600 px rendition), loaded after a 250 ms rest; no API request.
Rules
The preview never covers the image it shows; touch: a tap stays the viewer.
H5

Read ahead

optional, off

Resting 600 ms on a link that opens here reads its record, so the click is instant; the link gets H2's green dot. Without H3 this is how a resting pointer helps at all.

Cost
One request per link rested on, through the rate gate; MusicBrainz only, never another site.
Rules
A setting, off by default.
H6

Where Back goes

recommended

Resting on ← Back names the page it returns to: "Back to: Release · Greetings From Asbury Park, N.J.". The path in the title shows only the last three kinds.

Cost
None.
Rules
Also on ‹ › (the previous / next row's title).
Open questions

What to decide before building

1. Which ones

Recommended: H1, H2, H3, H4, H6 now; H5 later, as a setting

H1, H2 and H6 cost nothing; H3 and H4 are the page's own rules carried into the window.

2. The Ctrl rule inside the window

Recommended: the page's rule

The page shows a card with Ctrl held unless "card without Ctrl" is on. Inside the window the pointer rests on links all the time while reading, so a card without Ctrl could be busy. Same setting as the page, or always Ctrl inside the window?

3. Links that open a new tab

Recommended: H1 and H2 only

A link the window cannot open (a page of another site with no reader) gets the ↗ and the foot line, no card. Or the generic link card the page shows for other sites?

4. Phone

Recommended: tap = click, long-press = card

No hover on touch: a tap keeps doing what a click does; a long press shows H3's card or H4's preview, and lifting the finger leaves it open until the next tap.

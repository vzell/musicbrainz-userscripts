1aWhat exists today

Every picture the script shows ends in the same viewer (V). How it gets there differs: four separate displays, each with its own markup, card and click path.

AArt section

MusicBrainz release-tracks “Cover art (N)” and event-overview “Event art (N)”. About 1,100 lines of _releaseArt*, one descriptor _artSectionDesc('caa'|'eaa').

Type chips (multi-select), Grid / By type / Spreads, ★ main front, ⏳ pending, medium thumbs in the h3s, loading/none/retry, remembered layout, tab click opens the viewer.

BForeign detail head

The pictures of _fdHeadInsertSections(): SL item “Scans”, Discogs “Images”, archive.org “Pictures”. Card fd-pic, click _dpArtViewerClick().

Flat grid only (it borrows A's CSS and nothing else). One h2 per SL copy, so two viewers. A copy without scans disappears.

CFICE

The foreign image card engine: picture triggers in TABLE ROWS (SL Cover, JL Art, BS Photo, BB Media, DG Image, IA Art). _fiProvider() per host, B1 card _artCardCoreHtml(), _fiClick(), the 🖼 gallery _fgal*.

Shift+← → steps rows. Types per host (JL and IA from file names).

DGPE window strips

The link preview's Space window #mb-dp-dialog: a release's cover art, a Springsteen item's cover and scans, Discogs and archive.org pictures. Flat strips; _dpArtViewerClick().

The hover card's thumbnails are not clickable.

VThe viewer

#mb-art-viewer, _artViewerOpen(ctx, path, indices, start, opts), 13 call sites. Takes archive records or external ones {image, thumbnails:{250}, types, comment, external:true}.

Grid, Info, Slideshow, Rotate, Flip, Fullscreen, Download, Original, zoom/pan/pinch, background.

1aGPE and FICE are not the same thing

They are neighbours. The GPE previews any link (hover card #mb-dp-peek, Space window #mb-dp-dialog). FICE is the picture card and click for table rows, drawn in the stat tooltip #mb-stat-tooltip. They share the data layer below them and the viewer, never their UI.

Solid: data and the click to the viewer. Dashed: hover cards through the stat tooltip engine. The GPE's own hover card (#mb-dp-peek) is a separate engine and shows non-clickable thumbs.

1bThe viewer: what it could add cheaply

The viewer is the one piece every page already shares, so anything added here lands on MusicBrainz and on every foreign site at once. New buttons are outlined in amber. Try them: the sliders, Compare, the loupe, Copy URL and the ? overlay all work in this mockup.

M5

Viewer with Adjust, Compare, Loupe, Copy URL and key help

recommended
Adjust
CSS filter on .mb-artv-img, written beside the transform by _artViewerApplyTransform(); reset on step like rotation. Makes a dark scan or a faded insert readable. Download stays the original file.
Compare
Two images side by side (key C, then pick the second in the filmstrip). The release section's Spreads pairs open straight into it.
Loupe
Key L: a round 2.5× lens under the pointer, read from the large image already loaded. Matrix numbers and small print without zooming the whole stage.
Copy URL
Key Y: the image's own URL (archive or site) to the clipboard. With Shift: as a MusicBrainz edit-note line.
Key help
?: the overlay with every key. Today the keys live only in HELP.

2aOne image section for every detail page

A takes the generic part of the Cover art section (about 60 % of it: the sheet, chips, layouts, click routing, viewer order, Spreads, medium assignment) and lets an adapter say where the images come from and how to group them. MusicBrainz's Cover art and Event art become two adapters; B's three sites become three more. The panels below are drawn by one renderer in this page, fed by four adapters, which is exactly the proposal.

2bA table view, filtering and sorting

The fourth layout. Every row is an image: thumbnail, position, group, types, comment, flags, file. Click a header to sort, type to filter; the viewer then steps through the rows as shown. Tile size and “Show missing” work in every layout.

M4

Table view on the MusicBrainz release (12 images)

recommended
Where
A plain table inside the section (recommended): the GF, the sub-table filters and the findings counts stay exactly as they are. The alternative, a real table.tbl, would bring the 📊 dropdown for free but would join the page's table count, the global filter and every render pass.
Sizes
Pixel size and bytes are known only after an image loads (the viewer's facts); the column fills in as images are seen and makes no request of its own.
Open
This is the one decision left for vzell: plain table or table.tbl.

2aHow to get there

Five phases, each its own branch with specs that fail before and pass after. P0 changes nothing visible, so it can be judged by the existing suite alone.

P0

Extract the component, behaviour identical

Move the generic _releaseArt* code behind an adapter; caa and eaa become adapters. Scope every query to its own section (today document.querySelector('.mb-release-art-sec') assumes one per page). Gate: the MusicBrainz fixture suite plus the five Cover art specs and two Event art specs; repoint scripts/mutations/release-tracks-cover-art*.json.

P1

The foreign head onto it

_fdHeadInsertSections()' picture loop and fd-pic card become one adapter fed by spec.pictures. SL, Discogs and archive.org get chips and Grid / By type at once. Specs sl-item, ia-details, discogs-*-tracks, sl-image-card.

P2

Groups and placeholders

spec.pictureGroups becomes groupOf: SL copies in one section, “By copy”, and the missing copy as a placeholder. Discogs ★ primary, archive.org types from file names.

P3

Medium thumbs off MusicBrainz

_releaseArtApplyMediumArt() loses its release-tracks / CAA_CTX wiring; an adapter supplies mediaOf() (Discogs “Record N” from _dgReleaseMedia(), archive.org “Disc N”) and mediumOf(im). _releaseArtMediumAssign() is already pure and is reused as is.

P4

New views

Table view, tile size, Show missing; then the viewer's Adjust, Compare, Loupe, Copy URL and key help (they do not depend on P0–P3 and can go first).

S1

Skill sketch: add-image-section

with P1

A skill like foreign-detail-pagetype that wires the component onto a pageType. What it asks for, in the order a new site needs it:

{
    key: 'sl-item',                  // one adapter per pageType family
    label: 'Scans',                  // h2 text; N is counted, never typed
    load: (page) => records,         // or a Promise; external records, no fetch at render
    entityKey: () => 'sl:5472',      // viewer path and cache key
    groupOf: (im) => im.copy,        // 'Copy #1' … or the first type
    groupLabel: 'copy',              // chip row label, "By copy"
    badges: (im) => im.front ? ['★'] : [],
    placeholders: (page) => [{ group: 'Copy #1', note: 'No scans available yet' }],
    mediaOf: null,                   // () => [{pos, format, h3}] for medium thumbs
    mediumOf: null,                  // (im) => pos | null, never a guess
    views: ['grid', 'group', 'table'],
    setting: 'sa_sl_item_pictures',  // inside the site's own opt-in
}

The skill's checklist: adapter, records from the page already read (no new request), a fixture from debug/<site>-*-final.html, a spec per view plus one for the viewer's order, a mutation list, the coverage registry row, and a line in the site's docs/claude/<site>.md.

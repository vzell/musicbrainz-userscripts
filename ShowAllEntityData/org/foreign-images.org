Findings that change the design:

- *springsteenlyrics*: the list's cover IS the item page's cover (same URL). The scans
  exist only on the item page. The list already prints "artwork available" (the Artwork
  column: 35 of 50 rows on =sl-bootlegs-page1=), so a row without it needs no request.
  A brucelegs item page also shows the covers of related items (the same show's other
  releases): only the card's own =.col-md-2 img= is the cover — =_dpParseSl= already
  does that.
- *jungleland*: the labels are in the file names (=front=, =back=, =cd1…=,
  =booklet1…=) and map onto MusicBrainz's types (Front, Back, Medium, Booklet), so the
  card can use the grouped layout and type chips.
- *brucespringsteen.it*: at most one photo, often none (all four CD-R pages); thumb =
  full. Presence is known only after the page is read → a three-state cell.
- *brucebase*: the gig pages hold typed folders — =gallery:<gig>= (photos),
  =files:ticket-YYYY=, =files:pass-YYYY=, =news:<gig>= (clippings) — which match the year
  page's Media icons (Photo, Ticket, Memorabilia, News). Every page also carries the
  side bar's promo image (=files:artwork-disco/disco_livefromasburypark_rsd26.jpg=,
  linking =/retail:=); a reader must skip it. =_dpParseBb= reads only =/song:= pages and
  no images; a =/gig:= reader is new.

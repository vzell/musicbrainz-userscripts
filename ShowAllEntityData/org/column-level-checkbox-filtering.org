** 1. Who governs what today

- The three levels always AND together, and every =runFilter()= pass starts from the source rows
  (=allRows= / =groupedRows=); =renderGroupedTable()= then re-applies each sub-table filter on top.
- There are no column-level boxes. A column filter borrows a wider level's Cc/Rx/Ex:
  - single-table: the *global* boxes (=runFilter()=, =getColFilters(_singleTable, isCaseSensitive, isRegExp, isExclude)=)
  - multi-table: the *sub-table* boxes inside the 🔍 panel (=_colIsRegExp = _subRxCb ? _subRxCb.checked : false=);
    the global boxes reach the global query only.
- 📊 value sets inherit the same owner's Cc and Ex (=getColFilters()= → =f.isExclude=).

** 4. Proposal

- Every query owns its own three boxes: global → global query, sub-table → sub-table query,
  column → that column's text and 📊 selection. Levels still AND; narrower adds a condition,
  it never switches off a wider one. Plain and Rx both test per cell (F6).
- Setting =sa_enable_column_filter_modes= (default true). Off = today's borrowing; F3–F7 fixed either way.
- Ctrl+Click on a global/sub-table box also sets that mode on every column in scope.
- UI: variant A (Cc/Rx/Ex chips inside each filter cell, faint until hover/focus, Ex turns the
  field pale red) recommended; B (one mode button + popover) as the narrow-column fallback;
  C (extra mode-strip row) rejected: one extra header row per table.
- Performance: no per-row work added (3 attribute reads per non-empty column filter per pass);
  the F6 per-cell global match is the one hot-path change and needs an A/B before merging.

**** GPE and FICE: not the same thing

- *GPE* (generic popup engine) previews *any link*: the hover card =#mb-dp-peek= and the Space
  window =#mb-dp-dialog= (=_popSources()=, =_DP_SITES=, the =_ext*= readers). Pictures are one
  thing its window can show (D).
- *FICE* (foreign image card engine) is the picture card and viewer click for *table rows* on
  the foreign hosts (C): its card is drawn in the stat tooltip =#mb-stat-tooltip= through
  =_mbttResolve()= (=fi-img=), its click is its own window-capture listener (=_fiClick()=).
- What they share is *below and after* the UI: the detail-page reader (=_dpGet()=, =_dpMem=,
  its own IndexedDB, the per-site rate gates) — a row the link preview already read costs FICE
  nothing — and the viewer. Where they meet: a FICE trigger inside a GPE window (Discogs window
  tables, =_DGW_FI=) gets the window's ring, but its card, click and Space are FICE's.
- B is a third path again: the head's =fd-pic= card is deliberately not FICE, because FICE is
  shaped around rows (=rowFor()=, row stepping). Diagram in the mockup ("GPE vs FICE").

#+begin_src js
{
    key: 'sl-item',                  // one adapter per pageType family
    label: 'Scans',                  // h2 text; N is counted
    load: (page) => records,         // archive fetch (caa/eaa) or records already read
    entityKey: () => 'sl:5472',      // viewer path and cache key
    groupOf: (im) => im.copy,        // 'Copy #1' …, default: first type
    groupLabel: 'copy',              // chip row label, "By copy"
    badges: (im) => im.front ? ['★'] : [],
    bookTypes: ['Liner', 'Booklet'], // Spreads; caa only today
    placeholders: (page) => [{ group: 'Copy #1', note: 'No scans available yet' }],
    mediaOf: null,                   // () => [{pos, format, h3}] for medium thumbs
    mediumOf: null,                  // (im) => pos | null, never a guess
    views: ['grid', 'group', 'table'],
    setting: 'sa_sl_item_pictures',  // inside the site's own opt-in
}
#+end_src

1a. What exists today. There are four separate ways of showing a release's pictures, and all of them open the same viewer:
- A. MB release-tracks Cover art section (and Event art on event pages). It is the only one with type chips, Grid / By type / Spreads, the ★ main-front badge and the medium thumbs in the h3.
- B. The head on SL, Discogs and IA detail pages (Scans, Images, Pictures). It shows a flat grid only. Two SL copies become two separate sections with two separate viewers.
- C. FICE, which covers picture cells in table rows on the non-MB sites.
- D. The GPE popup window's image strips.

There is a real bug on SL 5472. The site shows copy #1 with "No scans available yet". Our page drops that copy without a word, while its Release card still says "Copies: 2". This needs fixing whether or not the refactor happens.

GPE and FICE are not the same thing.
- GPE: previews any link, as a hover card or a Space window.
- FICE: the picture card and viewer click for table rows on the non-MB sites.
- What they share: the cached page reads underneath them and the viewer, not their UI.
- The SL/DG/IA head (B): a third path again.

1b. Viewer suggestions, ranked by cost. The cheap ones are image adjust (brightness, contrast, grayscale, invert), a ? key-help overlay, copy image URL, a loupe and compare-two-images. They would use keys A, C, E, L, Y and ?, which I checked are free in the viewer's key handler today.

* TODO Is it possible to support springsteenlyrics.com

Is it possible for our userscript to optionally to support the springsteenlyrics.com website, specifically pages of the
following type, collections and bootlegs

#+begin_example
collections - https://springsteenlyrics.com/collection.php?cmd=list&category=album&f_format=12i - raw HTML of initial rendered page - @debug/sl-collections-initial.html
bootlegs - https://springsteenlyrics.com/bootlegs.php?cmd=list&category=aud_live1967 - raw HTML of initial rendered page - @debug/sl-bootlegs-initial.html
#+end_example

They all look like paginated pages which describe Bruce Springsteen releases

#+begin_example
@debug/collection-release.html - a specific collection release
@debug/bootleg-release.html - a specific bootleg release
#+end_example

Both URL are rendered unauthenticated

** Answer (2026-10-04, branch =sl-support=)

Yes — implemented as two opt-in pageTypes, =sl-collection= and =sl-bootlegs=,
behind the new setting =sa_enable_springsteenlyrics= (default OFF). Scope as
decided: every =collection.php?cmd=list…= and =bootlegs.php?cmd=list…= URL (any
category, any =f_*= filter); list cards only, no item detail pages fetched.
(The two "release" files are saved as =debug/bootleg-collection.html= and
=debug/bootleg-release.html=; both are single list cards, not detail pages.)

- Design and rules: =docs/claude/springsteenlyrics.md=; root-cause/probe log:

  lists".
- Verified live with the working copy: album/12i → 539 rows from 6 pages,

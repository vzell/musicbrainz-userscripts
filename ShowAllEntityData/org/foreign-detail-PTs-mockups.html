ShowAllEntityData · design study · 2026-11-03

Three detail pages, built like a MusicBrainz release

Can a setlist.fm setlist, an archive.org item and a Discogs release get a pageType like MusicBrainz's release-tracks: a button that turns the page into the script's tables, one sub-table per medium or set, credits split into columns, images on top, a facts box, and every column filterable and sortable? Yes, all three. The mockups below use real data from the test fixtures.

setlist.fm setlist feasible · new PT

URL
/setlist/<artist>/<yyyy>/<slug>-<id>.html
Rows from
the page itself (ol.songsList), no request, no key
Key adds
MusicBrainz ids of covered artists and guests (one API request)
New
@include, sfm-setlist PT, a parser of the setlist list (none exists)
Reuses
set times parser, MusicBrainz glyph, YouTube ▶ (song search)

archive.org item feasible · new PT

URL
/details/<id> (not @user)
Rows from
one anonymous /metadata/<id> request, the one the item's card already makes and caches; no key
Page itself
server-rendered, no shadow DOM; audio items embed the same JSON (input.js-ia-metadata)
New
@include, ia-details PT, a per-file parse (track no., size, md5, derivatives)
Reuses
pictures + viewer, ▶ archive.org player, Brucebase links

Discogs release feasible · upgrade dg-release

URL
/release/<id> (PT dg-release exists)
Rows from
the API answer it already reads (one request + the master's versions)
Today
one Tracklist (Pos, Title, Duration, one Credits cell), Credits, Companies, Identifiers, Other versions
Missing
a sub-table per side or disc, credits as role columns, sortable Length, images, facts
Reuses
the API record, image viewer, MusicBrainz column, 📊 Credit details

** Open questions (ask together with the mockup)

1. *Ctrl+click on a genre link.* The prompt wants a plain click to open the tag and Ctrl+click to
   open the editor's own tag (=/user/<me>/tag/<genre>=). Today Ctrl+click anywhere in the window
   opens a new tab (=_dpDrill()= bails on any modifier). Proposal: on tag links only, Ctrl opens
   your tag in the window; middle-click and Shift still open a new tab; the foot line says so.
2. *Image history from musicbrainz.org.* =…/images/update= is an edit page and needs the Discogs
   login. Link previews send external requests =anonymous= (detail-pages rule), so from
   musicbrainz.org the window can only show the API's data (type, W×H) — no uploader, no date.
   On discogs.com itself the page is same-origin and everything is there. Accept the fallback?
3. *Annotation version.* Listed without a wish. Leave as is?
4. *Documentation.* =/search?type=doc= is rendered client-side by Google's custom search, so
   there is no HTML to read. Probe =wiki.musicbrainz.org/api.php?action=query&list=search= first
   (CLAUDE.md probe rule); if it answers, the window lists the hits and opens =/doc/<Page>=
   inline. If not: only =/doc/<Page>= links get a reader.

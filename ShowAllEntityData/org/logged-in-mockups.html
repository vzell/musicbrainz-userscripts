1a + 1b · credentials and Cloudflare

You log in in the browser. Nothing else holds the password.

The script never asks for a user name or password and never logs in itself. It only rides along on the session your browser already has. Its list and detail fetches on SL and BB already send that session today, so in your own tab the extra content is there; the converters just skip what they do not know yet.

Your browser password lives here only

  • You log in on the site's own form.
  • Session cookie and Cloudflare clearance cookie stay in the browser's jar.
  • Same-origin fetch() (list pages, detail cards on the site) sends them automatically.
  • Cards opened from MusicBrainz stay anonymous (_extFetch, anonymous: true): the public view.

The userscript reads the page, not the jar

  • Detects the state from the page: SL shows a password field when logged out; BB shows "Sign in" in #login-status.
  • Stores the state with each cached detail card, so a public and a logged-in copy never stand in for each other.
  • Adds logged-in-only columns only when the fetched pages have them.
  • No sa_* setting for user or password, ever.

Claude sees structure, not you

  • Gets the probe's redacted JSON from debug/.
  • Logged-in fixtures only from pages you choose to save, scrubbed before commit.
  • Later: Playwright login state in playwright/.auth/, with a permissions.deny rule so Claude's tools do not read it.

What the chips mean

  • ● Logged in: every page of this run came back logged in.
  • ○ Public view: logged out, or the cards came from another site.
  • A mixed run (session expired halfway) says so, with the page where it changed.

Cloudflare (SL only)

  • In your tab it never bites: same-origin requests carry the clearance cookie.
  • It bites cross-origin anonymous requests, Python, and later Playwright, whose clearance is tied to browser and IP.
  • Today a challenged page reads as "0 cards". A _slIsChallenge() check names it, as above.
2 · finding out what logging in adds

The probe asks every page twice and keeps only the difference

scripts/probe-logged-in-diff.user.js, a throwaway Tampermonkey script. Run it from the Tampermonkey menu while logged in. Each probed page is fetched without and with your cookies, compared in the browser, and reduced to headings, tab labels, table headers, link kinds, image counts, form field names and short redacted excerpts. You review the JSON and download it into debug/.

Example output

The values shown are made up apart from the two byte sizes, which are from org/iframe.org X9. The real run fills this in.

What never leaves the browser

  • Cookies and form input values: not read at all.
  • Your user name: found on the page, plus any terms you type in, replaced by «USER».
  • E-mail addresses, long token-like strings, session-like URL parameters.
  • Link URLs: only their kind (gig:, collection.php cmd=list ?category).

Checked

node scripts/check-probe-logged-in-diff.js: a planted logged-in block is found, and none of the planted secrets reaches the report. Switching the redaction off makes it fail.

4a · artwork on the non-MusicBrainz pageTypes

One foreign-art path beside CAA/EAA, never inside it

The CAA/EAA column pipeline is built around MusicBrainz: archive URLs, MBID patterns, the caa extractor. Bending it to foreign sites would put MusicBrainz at risk. The artwork viewer and the summary panel already take any list of images (_DP_ART_CTX does this for cards). So foreign art gets its own small path, with its own setting, sort key and cache keys, and reuses the viewer.

Guard rails for MusicBrainz

  • New setting per site (e.g. sa_sl_art, default off), under each site's own opt-in.
  • Own sort-key class, added to _CLEAN_STRIP_SEL and _sortCellText(); never .mb-caa-sort-key.
  • Own cache keys (fa:<url>), never an MBID path in the art cache's metadata store.
  • The foreign-site specs that assert zero CAA/EAA requests stay as they are, and the MusicBrainz fixture suite must pass unchanged.

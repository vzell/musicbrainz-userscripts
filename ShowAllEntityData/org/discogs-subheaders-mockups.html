Discogs tracklist subheaders

Release 2012001, Manfred Mann's Earth Band – Bootleg Archives Volumes 1-5: 5 CDs, 57 tracks, 11 headings. Discogs draws every heading as a shaded row, and they come in two levels: a volume ("Volume 1: Live In Europe, 1981") and a show inside it ("Cologne 13/02/1981"). Our Tracks view keeps the volume in the disc heading and flattens the shows into a Section column. These mockups show how the shows could stay visible as groups, on the page and in the link preview.

What happens now

  • _dgReleaseMedia() already splits the headings correctly: a heading right before a new disc names it ("Volume 1: …" → h3); every other heading becomes the Section of the tracks after it.
  • So the level rule the mockups use exists today. Nothing new has to be guessed from the data.
  • What is missing is only the drawing: the Section column is the 3rd column of a 6-column table, the same weight as a title.
  • The window (_extDgTracklistHtml()) draws every heading as tr.mb-dg-thead: italic, grey, no level. A disc heading and a show heading look the same, and neither says how long it is.
  • The hover card says "Tracks 57" and nothing about the structure.
Numbers used throughout (sums of track lengths): Disc 1 · Cologne 2 tracks 10:42 · Paris 8 · 51:49 · Vienna 2 · 6:54 · Unknown 1 · 7:13. Disc 3 · Köln, Germany 11 · 1:04:47 · London, England 2 · 11:34. Discs 2, 4, 5 have only their volume heading.

A · Bands

  • A band per show, inside the disc table, in Discogs' own place and colour family. It reads name · N tracks · length, and a click folds that show.
  • Disc 1's table scrolls in its box here so you can try the sticky band: it docks under the column headers while its tracks pass.
  • The Section column is gone from view. It stays available to the 📊 dropdown and to the column chooser, so "filter by show" still works.
  • Sorted by another column the order is no longer the show's, so the bands step aside and each title carries a small show tag. The same thing the window's List tables already do for an event's "Soundcheck / Concert" parts (tr.mb-dp-tsec → .mb-dp-tpart).
  • Filtered, a band stays above its matches and reads "2 of 8"; a show with no match drops its band.
  • Disc 3: the stacked "Köln, Germany" becomes the first band, right under the column headers.
What the engine has to do. Every tbody tr counts as data today (row counts, filter, sort, 📊, odd/even, copy, clones). Real band rows would have to be skipped in all of them. Lighter route: draw the band on the first data row of each show, from a data-mb-sec attribute and CSS (an extra top padding plus a label across the row). Attributes survive cloneNode, so nothing is re-wired, and no row is added. Folding a show then means hiding rows by that attribute.

B · Nested

  • Under the disc heading, one small heading per show with its count and length, and its own table.
  • The disc heading carries the shows as chips (click one to jump).
  • Discs without shows (2, 4, 5) keep one table as today.
  • Downsides you can see: column widths differ from table to table, the column headers repeat for a two-track show, and Disc 1 grows from 1 table to 4.
  • Every per-table control (filter bar, 📊, the ⋮ menu, row count) would repeat per show.
What the engine has to do. The grouped render knows one level: h3 + table pairs. A show level means either a new nesting level in renderGroupedTable() (h3 → h4 → table, the master toggle and every h3-keyed feature taught about it), or flattening to "Disc 1 · Cologne 13/02/1981" h3s, which loses the disc as a unit (its length, its art in the heading).

C · Ribbon

  • Today's table as it is, Section column included, with three cues: a coloured stripe on the left per show, a heavier top rule where a show starts, and the show's name strong on its first row only (dimmed on the rest).
  • The disc heading lists the shows as chips with count and length, in the stripe colours.
  • Sorting and filtering work exactly as today. Sorted by Length, the stripes still tell the shows apart; the "start" rule is drawn only in # order.
  • No folding per show and no sticky label. You still read a column, but you see the boundaries at a glance.
What the engine has to do. Two attributes on each data row (data-mb-sec-i for the colour, data-mb-sec-start), set by the converter, plus CSS. Both survive cloneNode. The chips are a few spans in the h3. Nothing in filter, sort or the row caches changes.

Preview: card and window

  • Card: "Tracks 57" becomes Tracklist · 57 tracks on 5 CDs · 6 shows. "Shows" because that is what this release's headings are; the generic word would be sections.
  • Window: the tracklist as a two-level outline. Discs as shaded bars (DISC 1 · the volume · 13 tracks · 1:16:38), shows as indented italic rows with their count and length. Both fold.
  • A strip of chips above the list jumps to a disc (solid) or a show (dashed).
  • Track rows and their "▸ 3 credits" toggles are unchanged. Discs 2–5 start folded here only to keep the mockup short; whether they start open is a question below.
  • The disc split is the page's own (_dgReleaseMedia()), so the page and the window always agree on what Disc 3 is.
What the window has to do. _extDgTracklistHtml() renders from _dgReleaseMedia()'s media and sections instead of the flat list; the record already carries everything (no request more). Fold state joins _extDgCollapsed. A record version bump, since the output changes.

1 · Which page variant?

A (bands, as on Discogs), B (a table per show) or C (ribbon on today's table).

My pick: A, drawn on the first data row of each show (see A's engine note), so no row is added and the engine's row handling stays as it is. C is the fallback if that drawing turns out fragile.

2 · Sticky bands?

In A, should a show's band dock under the column headers while its tracks scroll past?

Yes on desktop; off on touch devices, where it eats too much of a small screen.

3 · The Section column

Hidden by default once the bands show it (still in 📊 and the column chooser), or kept visible?

Hidden by default, so the bands do not say everything twice.

4 · Window outline: open or folded?

Should all discs start open in the window, or only the first, or all folded with the chip strip as the index?

All open up to about 40 tracks; above that only Disc 1 open.

5 · The card's word

Always "sections", or a word from the data when it is obvious (shows, parts, sides)?

Always "sections". Guessing "shows" from date-like headings is cute, but wrong on the first studio box set.

6 · Masters too?

A master's window shows its main release's tracklist the same way. Same outline there?

Yes, it is the same renderer.

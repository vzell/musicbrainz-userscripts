## Your two questions

**`data-mbu-foreign`: what is it for?** It has nothing to do with EH's TOC. On a release page SAED copies MusicBrainz's tracklist rows into its own tables, one per medium, with sort buttons, a 📊 value panel per column, filters and so on. Those rows keep MusicBrainz's row ids (the track MBIDs), and ISRC Scout's observer adds its columns to any table holding such rows. So:

- `fillTrackData()` added a second set of bare ISRC/Links cells to SAED's tables,
- `showTrackData()` (after a release load, the modal, a settings change, …) removed SAED's rebuilt cells everywhere in the document and refilled them bare, without SAED's header buttons and with the colspans bumped again,
- and `mbuTip` showed its tip over SAED's own hover card.

That's #839. The marker says "this table is a rendered copy owned by another script", and your commit does exactly what I hoped for: ISRC Scout and `mbuTip` leave it alone. SAED now puts `data-mbu-foreign="saed"` on every table it renders.

**`data-ii-platform`: why?** SAED turns ISRC Scout's Links icons into a filterable, sortable column: a 📊 section "Links info - Platform" with a count per platform, `Spotify` typed into the column filter, and so on. The icons are SVG without text, so the platform name came from the tooltip. When `title` became `data-tip` on 2026-11-06, that silently stopped working. A data attribute is a contract; tooltip wording isn't. SAED now reads `data-ii-platform` first and falls back to `data-tip`, then to the old `title`, so every ISRC Scout version works.

## One request: V under `data-mbu-keys-off`

`data-mbu-keys-off` suspends every EH command, **V included**. For a modal window that's right. But SAED's table isn't a modal: it's the page, and V is how users move between EH and SAED. So SAED does **not** set `keys-off` and keeps its own narrow key guard instead.

Could the on/off toggle (V, or whatever key it is rebound to) stay active under `keys-off`, e.g. through an opt-in value like `data-mbu-keys-off="saed keep-toggle"` or a separate `data-mbu-keys-keep="toggle"`? Then SAED would set `keys-off` while its table is shown, which would also cover keys a user rebound in EH's palette (SAED can't know those today).

## Done on SAED's side in the meantime

- SAED's tooltips, menus, dialogs and the sidebar handle no longer die when SAED starts under EH and EH is switched off. They were appended to `document.body`, which is EH's body at that moment; they now always live in MusicBrainz's body.
- EH's single-letter keys are ignored on MusicBrainz's page, as above.
- Leaving from EH's view: after a render, a click in EH's view no longer gets SAED's "you are about to leave" question. EH opens most pages in place, and the table stays. Only a real unload (a page EH loads, or V after EH navigation) gets the browser's own "Leave site?" prompt.
- The four adoptions above: `data-mbu-foreign`, `data-ii-platform`, `data-mbu-quiet` and the ⋯ menu items.

All of this is in SAED's development version and goes out with its next release. If you'd like to try it next to your branch, the install link is in my previous comment.

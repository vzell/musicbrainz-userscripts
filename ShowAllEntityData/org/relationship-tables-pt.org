* The request

Tabelize the "Relationships" sections of more pageTypes the way
=event-overview= does (=applyEventDetailsToTables()=):

1. Pages whose only data is that section and that had no pageType: place,
   area, instrument overview.
2. Pages with a main table plus that section: series, work, release group,
   label and artist =/relationships= tab; recording (plus "Related works");
   release (h2 "Credits" with h3 "Release" and "Release group").
3. Question: can several h2 sections each have their own global filter,
   stats, status line, Clear/toggle buttons?

* Answer to 3

No. The engine keeps one live dataset per page: =activeDefinition= (364
references), =allRows= (142), =groupedRows= (204), =_filterResultCache=, and
the global filter's fixed =mb-global-filter-*= ids (69). Within it, every h3
sub-table has its own filter, count and collapse. Native h2 sections can be
collapsed, without filter or stats. Pages with two data sections
(=area-releases=, =artist-aliases=) use either/or buttons: pressing one
removes the other section, pressing again reloads. A multi-section engine
would be a separate, large refactor.

* Decisions (user, 2026-10-12)

- Coexistence: either/or buttons. Folding Relationships into the main
  dataset was rejected as risky; a multi-section engine is out of scope.
- The page's own "Show all…" button renders exactly as before; the native
  Relationships/Credits section stays a collapsible, non-filterable h2
  section. Only the new button builds tables.
- The new button removes the main data section for its render.
- Dates: Begin/End columns, both also through =dateParts= (B-*, E-*).
- Series positions: one Number column; Number and Order as soon as the two
  differ for an entry.
- Mockups first, then stop for review (done; reviewed with the points above).

* What was built

- =applyRelDetailsToTables()= + =_relRemoveMainSections()=, =_relTablesFeatures()=,
  =_relTablesButton()=, =_isRelTablesRun()=; attribute parsing =_relClassifyAttr()=,
  =_relPeelAttrs()=, =_relRowAttrs()=; opt-in options on =_eventRelColumns()=,
  =_eventRelRowsFrom()=, =_eventRelParseLine()=.
- Button keys: =type= (runs as that pageType), =replaceFeatures=, =showIf=.
  Disk load: =_buttonForSavedPageType()=, =_activateButtonForSavedPageType()=.
- A recording on no release keeps its Relationships button
  (=_noMainButton=) instead of drawing no toolbar.
- Settings group "🔗 RELATIONSHIP SECTIONS": =sa_enable_relationship_tables=
  (on), =sa_relationship_tables_one_table= (off), =sa_relationship_tables_related= (on).
- Found on the way, fixed: Picard's per-table release-link guard matched any
  href containing "/release/" (discogs.com/release/…, rateyourmusic.com/release/…).

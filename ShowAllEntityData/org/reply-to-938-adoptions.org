Hi @majkinetor,

a few more things I'd like to take into SAED from your scripts. I'd build items 1–6 on my side, but I'd like your OK
first, and to know if you'd prefer a particular form. SAED is GPL-3.0-or-later now, so the licence is fine for most of
it, and I've just moved my shared library, VZ_MBLibrary, to GPL-3.0-or-later as well. Anything I take gets a
credit in the header, like the gate.

1. **Credit Hoarder's role and instrument maps** (`src/data/entity-map.js`, `src/data/instruments.js`,
   `src/data/work-only-rels.js`). On Discogs release and master pages, SAED would show which MusicBrainz relationship
   each credit maps to. May I copy them? Credit Hoarder's header says MIT, the repo root says GPL-3: which applies?
   And would you consider publishing them as a JSON file both scripts read, so a fix reaches both?
2. **Apollo's `CONFUSABLE` table and Group Therapy's `FORMAT_EXCLUDE_DEFAULT`**, for two SAED findings: invisible or
   look-alike characters in names and titles, and a relationship that doesn't fit the format (e.g. "lacquer cut by" on
   a Digital Media release). OK to copy them as they are?
3. **Apollo's guess-case lists** (`UPPER_CASE_WORDS`, `POSTPROCESS_FIXLIST`, `VERSION_PHRASES`, the camelCase names),
   for SAED's MusicBrainz title style on other sites. OK to copy?
4. **Fusion's duplicate-recording gates** (`titleDistinctWords`, `isrcConflict`, `placeConflict`, `shouldUnion`,
   `gatedUnionFind`), for a "possible duplicate" finding on recording tables, with no extra requests. Would you rather
   I port them as they are, so SAED and Fusion agree, or re-implement the idea?
5. **`mbuLog`**: I'd like an in-page log window like yours (filters, Copy as Markdown), so users can send me a log
   without DevTools. It would live in VZ_MBLibrary (now GPL too). OK to base it on your code?
6. **Event Horizon's filter language**: SAED's global filter could get an optional query mode. I'd like to use your
   syntax (`col:value`, `-term`, `OR`/`AND`, brackets, quotes, ranges like `2022-2024`), so a query means the same in
   both. Is the grammar stable enough to follow, or are changes planned?
7. **One thing I'd ask you to build: a shared "drop" key for kept answers.** Event Horizon drops its kept answers
   when it writes to MusicBrainz (`kpWrote()` sets `localStorage['eh.kept.drop']`). I'd like SAED to keep its cached
   answers the same way, and both caches would stay right if every script read and wrote one common key, e.g.
   `mbu.kept.drop` (a timestamp; anything kept before it is a miss). Then an edit made with any of our scripts
   drops every script's kept answers, and the other way round. Would you add that (EH reading both keys
   for a while), and is the name OK?

No hurry on any of these.

Thanks!
Volker

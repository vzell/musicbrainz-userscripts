R5's key map, as built in the mockup:
- ← → step, wrapping at the ends; Home / End; touch: horizontal swipe
- click or Z toggles 2× zoom, the zoomed image follows the mouse
- G grid grouped by type (Esc from a grid opened via R4 closes; from a grid
  entered with G it returns to the image)
- I info panel, O original in a new tab, Esc close; focus returns to the opener

Learned while building the mockup:
- *The count is free.* "Cover art (16)" is in the tab text, so R1's collapsed
  h2 can show the number without any request.
- *Main front ≠ Front type.* Only one image has =front: true=; the ★ marker
  must read that flag, not =types.includes('Front')= (same lesson as the
  summary panel, see docs/claude/artwork-caa-eaa.md).
- *Spread pairing works on this release* ("opened gatefold cover, inside left"
  + "… inside right"), and "… inside" stays single. Liner pages have no
  comments, so their order is archive order — fine, but nothing to verify it.
- *Medium matching cannot work here*: 4 Medium images for 3 discs (probably
  labels for 3 discs plus one extra side or sleeve), no comments. A rule that
  matched by order would be wrong. Refusing visibly is the right default.
- The viewer must be progressive (as in the CAA/EAA study): the 250 px thumb
  is already loaded by the sheet; show it at once, swap on =load=.

** Request and performance budget

- Per page view: 0 requests before "Show all Tracks for Release". After the
  render (the section starts uncollapsed, as decided): 1 JSON request to
  =coverartarchive.org/release/<mbid>= (no published rate limit, no batch
  endpoint — see the root CLAUDE.md), or 0 on a =_caaImagesCache= / IDB hit.
- Thumbnails: =loading="lazy"=, 250 px (=small= on older records). As built
  they are plain =<img src>= (browser HTTP cache), NOT =_artFetchCachedImage()=
  — routing them through the IDB image cache is open.
- Viewer: 1200 px only for the image being viewed, ±1 neighbour preloaded.
- Off the hot path: the section is not a table, so filtering, sorting and
  rendering of the tracklist are unaffected. Still capture one
  =run-perf-comparison= on a release-tracks page with the section open vs
  =main= in the same session, ratios only, because the render tail grows.

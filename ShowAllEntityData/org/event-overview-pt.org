** The native event page (what the PT works from)

- =#content=: =div.eventheader > h1=, =p.subheader= ("~ Concert"), the tabs
  (Overview, *Event art (15)* → =/event-art=, Aliases, Tags, Reviews,
  Details, Edit), then the h2s Annotation, =h2.relationships=,
  =h2.related-series=, =h2.setlist=.
- *No =table.tbl=.* Relationships are =table.details=, one per target type,
  each row =<th>phrase:</th><td>= with =<br>=-separated targets. A target
  line is the entity link plus whatever follows: a disambiguation in
  parentheses, relationship attributes ("(time: 19:40 - 22-29, lead vocals,
  …)"), the area chain after a place ("in Manchester, Greater Manchester,
  …"), "(live, …) by <artist credit>" after a recording, "(order: 150)"
  after a series.
- *"Related series" mixes two things*: the event's own "part of" series, and
  then that SERIES' relationships (tour by, subseries of, official
  homepages, schedule). The latter describe the tour, not the event.
- Setlist: one =p.setlist=, =<br>=-separated lines: =strong= "Artist: <a>"
  lines; =span.comment= joining words ("&", "with", "and"); a blank line
  between parts; a =span.comment= right after a blank line is a part header
  ("Soundcheck", "Concert"); other =span.comment= lines are notes
  ("Scheduled: 19:30 | Local Start Time 19:40 / End Time 22:29"); song lines
  are =/work/= links, several joined by " / " for a medley.
- The "Event Schedule" h2 after the setlist is *another userscript's*
  (=sanojjonas=) block, not MusicBrainz markup. Leave it alone.
- Sidebar =div.event-art= is the same shape as =div.cover-art=.

** DECIDED (2026-10-06, by the user)

- [X] "Ship the pageType with C (every part a setting), T2 and S1 as the
      default layouts, and E1 + E2 for the art."
- [X] Read as: both layouts ship as the values of the two layout settings
      (C holds them), T2 and S1 the defaults, T1 and S2 the alternatives.
- [X] The setting keys and defaults as in the table above.
- [X] Event art remembers its own Grid / By type choice (a new GM key next
      to =MB_RELEASE_ART_LAYOUT_KEY=) — confirmed by the user.
- [X] Changed in implementation: the settings library (VZ_MBLibrary) has no
      select type, and adding one is a library change that the dev script's
      mirror =@require= would not even exercise live. So each layout choice
      is a checkbox, default off: =sa_event_overview_relationships_one_table=
      (T1), =sa_event_overview_setlist_one_table= (S2).
- [X] Changed in implementation: every converted table ends up in ONE block
      after =h2.relationships= — =renderGroupedTable()='s initial render
      removes every h3/=table.tbl= in =#content= and re-inserts all groups
      after the h2 before the first table, so the setlist cannot keep a
      section of its own without changing that core function. Its tables
      carry a "Setlist:" prefix instead (WIP.2).

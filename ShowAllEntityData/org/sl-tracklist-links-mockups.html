Song links and MusicBrainz works in SL tracklists

Each title in an item's tracklist links to its song page on springsteenlyrics.com. A MusicBrainz work glyph in front of it opens the work's card on hover. All numbers below come from probes of 5 Nov 2026: the whole SL lyrics index, Bruce Springsteen's 1,587 works on MusicBrainz, and 15 saved item pages.

210 / 282 tracklist lines on 15 saved item pages resolve to an SL song. All 72 misses are songs SL has no page for: other artists on VA sides, Castiles covers, "Intro".
1,305 / 1,334 SL base titles whose slug the rule derives (drop a trailing "(…)", keep a–z and 0–9). 4 more with a leading "(…)" dropped; 25 need the exception list.
732 + 412 SL base songs with an MB work: 732 exact (the work's annotation links the SL page), 412 by a unique title. 29 ambiguous, 208 none (mostly covers).
200 → "does not exist!" An unknown slug gets HTTP 200 and an error page (checked with song=seemyfriends). A link built by the rule alone can lead nowhere, so links need a list of known slugs.

What changes

  • The Title cell's text is wrapped in a link to lyrics.php?song=SLUG. The text, the filter, the sort and the 📊 dropdown see the same title as now; the "As written on the site" tooltip stays.
  • Hover shows the SL song card that already exists (POH); Space opens its window.
  • The link is built when the table is built, from the page's own text: no request.
  • Both of vzell's "assoc list" examples (A2, B2) are covered by the rule. The real exceptions are 25 titles, such as comeonletsgotonight, fortymilesofbadroad, angeleyes-sinatra.
Q1

Where does the list of known slugs come from?

A: an embedded list of the 1,381 base slugs (about 18 KB), rebuilt by a script from the lyrics index. A title not in it stays plain text. B: the rule alone, with a dashed link for an unverified guess. C: A, with a small tag naming the source of each link.

Recommended: A. A new SL song stays unlinked until the list is rebuilt; Q2's runtime index fills that gap.

Q2

Link this show's version when SL has one?

It needs every slug including versions (3,552), not only the 1,381 base ones. That list is too big to embed; the script would keep it as a runtime index in IndexedDB, filled by the lyrics index's "Show all lyrics" run or loaded once on demand (32 same-origin pages, about 40 s), 30 days.

Recommended: A, from the runtime index when it is there; without it, the main page (Q1's list).

What changes

  • The glyph is a plain musicbrainz.org/work/MBID link. On SL every such link in our tables already gets MusicBrainz's own card and window, so hovering shows the work's card with no new reader.
  • Matching, in order: a work whose annotation links this SL song (old /lyrics/<l>/<slug>.php or lyrics.php?song=), then exactly one work with this title or alias. On the 15 saved pages: 208 of the 210 SL songs match, 206 by annotation.
  • A title match is less sure: MB's "Wild Billy's Circus Story" has no SL link in its annotation, so it is dashed.
  • The column (B) is filterable and sortable (exact / title / several / none) and has its own 📊 section; the glyph (A) keeps the table as narrow as now.
Q3

Glyph (A), column (B) or both (C)?

Recommended: A, as you suggested. B is worth it only if you want to filter "songs without an MB work".

Q4

Show title-only matches (dashed) and several candidates (count badge, the card lists them), or only exact annotation matches?

Recommended: show all three states; the card says how it matched.

Where the MB work comes from

Bruce's work catalogue recommended

/ws/2/work?artist=70248960…&inc=aliases+annotation, 100 per request.

  • 16 requests, about 18 s at MusicBrainz's 1 request/s. Measured: 01:23:54 → 01:24:53 CET with a 503 retry.
  • Kept in IndexedDB for 30 days, like the "Recording of" work lists; every later item page is instant.
  • Gives SL slug → work exactly (752 annotated works) and title → works for the rest.
  • Its own cache entry: MusicBrainz's "Recording of" list keeps its requests and data unchanged.

The item's MB release add-on

/ws/2/release/MBID?inc=recordings+recording-level-rels+work-rels

  • One request; the release's own recordings give the work per track. Probed on Live/1975–85: 40 tracks, 40 works.
  • Needs the release MBID. Logged in, the item card has your MusicBrainz link. A url lookup of the item's address mostly fails: MB stores SL item URLs as entered, e.g. http://www.springsteenlyrics.com/collection.php?item=4994&category=album&pg=4, and 10163 has none.
  • Covers and live versions match exactly here, where a title match is unsure.

A search per title not proposed

  • One request per track (1 s each), fuzzy, and many hits for a cover title.
  • Would only help the 208 SL songs that are not in Bruce's works, mostly covers of other writers.

When it is asked

1

Press "Show the tracklist". The SL links are in the table at once.

2

Catalogue cached: the glyphs are built with the table, no request. Not cached: the glyph slots show faded, the progress popup reads "MusicBrainz works 3 / 16", and the glyphs fill in when it is done.

3

Logged in with an MB release on the card: one more request, and that release's works replace title matches.

Q5 · automatic recommended

Under a new setting sa_sl_mb_works (on by default, as every SL setting): the catalogue loads after the first render and is cached.

Q5 · on request

A ▶ MB button in the Title header, as Brucebase's MB-Event column has. Nothing is asked of MusicBrainz until you press it.

Where else

  • The item's card and window (POH) on any host, MusicBrainz included: its tracklist could link the songs too.
  • The song page's edition tables (sl-song, "Releases and versions"): other songs of the same release.
  • Medleys: "ROULETTE / outro", "Dear Mr. Fantasy - Hey Jude": a link per part when each part is a known song.
  • Various-artists sides (item 9685): only titles found in the slug list get a link, so Ted Nugent's songs stay plain.
Q6

Use your MB release link (logged in) as the first source?

Recommended: yes, as a second step after the catalogue.

Q7

Which other places in this branch?

Recommended: item pages and the item window's tracklist now; the song page's editions and medleys later.

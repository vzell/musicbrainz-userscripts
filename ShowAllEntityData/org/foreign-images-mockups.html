Foreign site artwork: hover card, viewer, click routing

On MusicBrainz a table image gets the liner-notes card on hover, the darkroom viewer on click, and Shift + ← → to walk the visible rows. discogs.com already has all three. These mockups show the same three on springsteenlyrics.com, jungleland.it, brucespringsteen.it and brucebase, built from rows in the committed fixtures and from images on the item pages the probe read on 2026‑10‑23.

0Where the pictures are

Only the springsteenlyrics card lists show an image in our table today, and it is a plain link to the item page. Everywhere else, the pictures sit on each row's item page, which the detail preview already reads and caches (_dpGet(), IndexedDB). The card and the viewer would read that same record, so they never cost a second request for a row whose preview was already opened.

1springsteenlyrics: the Cover column gets the card

The cover is already in the row, so the card can open at once with it. The scans come from the item page on the first hover. The list's own "artwork available" flag (the Artwork column) tells beforehand which rows have scans at all, so a row without it never asks.

2The viewer on a foreign row

The same #mb-art-viewer MusicBrainz uses, opened with an external context per host (as _DG_ART_CTX does). The stage shows the thumbnail at once and swaps to the large image when it arrives. The info panel is _artViewerInfoExternal()'s: position, host, size facts and both links, with no archive rows. Try ← →, Shift + ← →, G and I after clicking into it.

3jungleland: no image in the row today

Every jungleland entry has front, back, CD and booklet scans on its item page, labelled in the file name. The labels map onto MusicBrainz's own type vocabulary, so the card can use the grouped layout and type chips as the CAA column does. The question is where the trigger goes.

4brucespringsteen.it: one photo or none

A record page has at most one photo. The probe found one on all four LP pages and none on the four CD‑R pages, so whether a row has one is only known after its page is read. The cell therefore has three states, and the card is a single large image (the B2 shape) rather than a contact sheet.

5Brucebase: the Media icons open what they announce

A year page's Media column already says which kinds of material a gig page holds. The gig page has them in typed folders: gallery: photos, files:ticket-1985, files:pass-1985, news: clippings. Hovering an icon shows the card filtered to that kind, and a click opens the viewer on it, with every kind one ← → away.

7The table-wide 🖼 gallery

MusicBrainz's gallery (D2) reads only the caches and makes no request. On a foreign table that means it shows the rows already loaded and says how many are not. Loading the rest would be a long run at 1.1 s a page, so it is offered as an explicit button with its time, never done by opening the gallery.

R

Rules the implementation keeps

reference
  1. No request at render. A record is asked on hover or click only, through _dpGet() at its 1.1 s spacing. On its own host that is the same rule the detail preview follows.
  2. One record, one cache. The card, the viewer, the Art/Photo cell and the detail preview read one parsed record. A parser change bumps _DP_PARSER_VERSION.
  3. Late answers reach the source rows. A cell filled after render (J1, K1) is mirrored to the master row (_findMasterRowByIdx()) and owes the four filter-cache duties.
  4. One click handler, window capture. Plain left click only, so the navigation guard and new-tab clicks behave as today. _dgThumbClick() folds into it.
  5. External images stay external. referrerpolicy="no-referrer" everywhere, including _artCardCoreHtml()'s tiles, which lack it today. No art IndexedDB.
  6. MusicBrainz unchanged. Every new branch is host-scoped. The MusicBrainz fixture suite runs before merge.

A1

Stacked deck

Optional

The first three images fanned like a stack of sleeves, count pill on top. Reads as “there is more than a front” at a glance.

Requests
+2 thumbnails per row with ≥ 3 images
Risk
On a 2 000-row discography that is up to 4 000 extra fetches. Only acceptable if cards 2–3 load on hover.
A2

Type-coverage chips

Recommended

Which types exist, and which are missing: Front, Back, Spine, Medium, Booklet, Tray. A superscript counts repeats. ⏳ is added when an image awaits approval (none here).

Requests
0 — types come from the cached archive JSON
Risk
Chip text must stay out of filter and sort text: add its class to _CLEAN_STRIP_SEL.
A3

Mini filmstrip

Not recommended

Every image as a 22 px thumb, overflow as “+6”. Pretty, and the most expensive option by far.

Requests
1 per image per row, on render
Risk
Here +16 fetches; on a large page 10 000+. The 503 work exists to avoid exactly this.

BRicher tooltips

Today the icon's hover shows the front at strip size, and an image row's hover adds a small card holding the types and the comment. Both proposals keep the existing “liner notes” card look and its serif type, which needs no web-font request.

B1

Contact sheet on the icon

Recommended

Hovering the icon or the count answers “what art does this release have?” without a click. ★ marks the archive's chosen main front (img.front), which is not the same thing as “typed Front”. Berlin Night has two Front-typed images.

Requests
0 JSON. The 250 px thumbnails, which the cell already references, load on first hover through _caaQueue.
DOM
One singleton card, as today
B2

Preview with a metadata card

Recommended

Hovering one image row: the preview and its facts in one card instead of two floating boxes. It shows the position in the set and whether this image is the archive's main front or back.

Requests
1, the same preview fetch today's hover makes
Note
The archive JSON has no pixel size or file size. Those can only show after the original loads (D1).

CThe expanded cell

Berlin Night, 10 images. Today they stack vertically at 18 × 18 px, even though each one is a 250 px image already downloaded. Making them bigger costs nothing. Click any image to open the viewer at it.

C0

Current list

Reference

10 rows, about 220 px tall, 18 px thumbs. The image itself can only be seen through the hover preview.

C1

Contact-sheet grid

Recommended

Tiles of about 64 px with the type and comment on a scrim. Roughly 4× denser than C0, and the art is visible without hovering.

Requests
0 extra; same thumbnails as C0
C2

Grouped by type

As a toggle

One header per type, so “three discs, two tray cards” reads at once. A multi-type image sits under its first type and names the rest.

Requests
0 extra
C3

Filmstrip

Optional

One row high whatever the count, scrolls sideways with snap. Keeps rows short; hides most of the set behind a scroll.

Requests
0 extra

DA popup of its own

Modelled on Art Station's full-screen viewer: arrow keys move between images, ↑ ↓ and the wheel zoom toward the cursor, the image follows the mouse when zoomed, the zoom level is remembered, P runs a slideshow. Added for a table: Shift + ← → steps to the previous or next release in the table, so all 21 images are one continuous set.

D1

Lightbox viewer

Recommended

Live: click into the viewer and use the keys listed along its bottom edge. The info panel on the right is the same liner card as B1 and B2, so one renderer serves all three.

Requests
0 JSON. One large image per image viewed (1200 px), plus at most one neighbour preloaded on each side. All of them go through _artFetchCachedImage(), so they land in IndexedDB.
Opens from
A click on the icon, on any thumbnail in the cell, or on any image in the strip above the table
Touch
A tap opens, a swipe moves to the next image. A hover-only design would leave phones out.
D2

Table-wide gallery

Later phase

Every image in the sub-table, grouped by release, opened from the strip toggle or the 📊 summary. The type chips answer the bootleg collector's question: which releases are missing a disc or tray scan? Compare puts two releases side by side, type by type.

Requests
One 250 px thumbnail per image, only when opened; lazy-load beyond the first screen
D3

Docked side panel

Optional

Non-modal: the panel follows the hovered or selected row and the table stays usable. Good for scanning down a long list; it takes about 300 px of width from a table that is already wide.

Requests
As B1, per row shown
Risk
Competes with the sticky column and MusicBrainz's own sidebar on release pages

→Recommendation

Ship A2 + B1/B2 + C1 (C2 as a layout toggle) + D1. None of them adds a JSON request, and C1 and D1 make art that is already downloaded actually visible. D2 follows once D1 has settled. A3 stays out.

  1. P0 · Explain the size mismatch. In the snapshot, Berlin Night's preview source is a 250 px image and the others are 500 px, with two different URL prefixes. Find out which path wrote which before building a viewer on data-li-big-src.
  2. P1 · B1 and B2 tooltips, with the liner card renderer the viewer will reuse.

  6. P5 · D2 gallery.

The full plan, with the invariants each phase must keep and the specs each needs, is in org/redesign-CAA-EAA-column.org. Every component is driven by the CAA/EAA context, so event art gets the same treatment with its own types.

D1's key map, as built in the mockup:
- ← → image (crosses into the neighbouring release at either end)
- Shift+← → previous/next release
- ↑ ↓ / wheel zoom toward the cursor, 0 fit, click toggles 2×
- image follows the mouse when zoomed; zoom level remembered
- P slideshow, G grid of the current release, I info panel, O open original,
  Home/End, Esc close
- touch: tap opens, horizontal swipe steps

Two of these come straight from Art Station's full-screen viewer: the remembered
zoom and mouse-follow pan. Its edit actions (Enter edits the comment, Delete marks
for removal) are out of scope: this script reads, it does not edit art.

Learned while building the mockup: *the viewer must be progressive.* A 1200 px
image from coverartarchive.org (redirected to archive.org) can take seconds. Show
the 250 px thumbnail, already cached, at once, and swap in the large image on
=load=. Show a quiet "loading" note in the meantime, not an empty stage.

** Invariants the implementation must keep

From docs/claude/artwork-caa-eaa.md and docs/claude/filter-and-cache-invariants.md:

- *Presence sort* goes through =_sortCellText()= and =.mb-caa-sort-key=. New chip
  or tile markup must not leak into sort text.
- *Types and comments* are resolved by =_artSearchTextFor()= /
  =data-mb-art-search= / =_artSyncSearchTextToSourceRow()=, never by reading
  =ul.mb-caa-art-ul=. A new layout changes the rendering only, not the search
  text.
- *Keep the classes =.mb-caa-type-badge > span= and =.mb-caa-art-comment= in
  every layout.* The 📊 =arttype:=/=artcomment:= structure modes, the uniq-dropdown
  counts and =_artHighlightImageLi()= all select on them (grep
  =mb-caa-type-badge > span=). C1/C2/C3 tiles must carry them, visually
  restyled, or the filter highlight and the 📊 counts silently break.
- New visible text (A2 chips, tile captions) goes into =_CLEAN_STRIP_SEL=, or is
  rendered from a data attribute via CSS =::before=, so a typed filter for "B" or
  "M" does not match chip letters.
- *Expanded state*: both the FIRST-BUILD and REBUILD branches of
  =_artBuildMultiRowArtCell= restore expansion (=expandedCells=,
  =wasExpanded=). A layout switch must go through the same path.
- *Clone safety*: =renderFinalTable=/=renderGroupedTable= =cloneNode(true)=, which
  drops listeners. The viewer and the new tooltips are opened by ONE delegated
  listener, keyed on data attributes (release path + image index), never by
  per-element =addEventListener=. The mockup does exactly this
  (=document.addEventListener('click', … closest('[data-open]'))=).
- *Master-row mirroring* on =tableMode: 'multi'=: anything appended to a live
  row must reach the source row (=_findMasterRowByIdx()=,
  =_buildMasterRowIndex()=). The viewer should read from =ctx.imagesCache= by
  entity path, not from DOM, which side-steps this.
- *Driven by =ctx=*, never the literal "CAA": the same viewer serves EAA
  (=ctx.column=, =ctx.toggleLabel=, event-art types such as Poster).
- *Touch*: =_isTouchCompatMouseEvent()= guards every hover handler. The viewer
  opens on tap and steps on swipe; a mobile spec covers both.
- Hover texts through =_setTip()=; cards use =.mb-tt-liner= rows
  (=.mb-tt-title=, =-pill=, =-comment=, =-dim=, =-rule=, =-foot=); no inline
  colours.
- CSS: extend shared selector lists, never copy a block; *no backtick inside a
  =GM_addStyle= comment*.
- Summary-panel rule carries over: *do not add a request to enrich* tooltips or
  the viewer's metadata. Everything comes from =ctx.imagesCache=.

** Request and performance budget

- B1, B2 metadata, C1, C2, C3 and D1 metadata: 0 JSON requests.
- Thumbnails stay =loading="lazy"=, so hidden ones are not fetched; they load
  only when shown (expand, B1 hover, viewer filmstrip).
- Viewer images (1200/original) are user-initiated. They go through
  =_artFetchCachedImage()= (session Map → IDB → GM_xhr) and the shared
  =_caaQueue=, with at most ±1 neighbour preloaded.
- A3 (and A1 without hover-loading) is a request regression: N thumbnails per
  row at render. Flag it per CLAUDE.md "Performance is a priority" before any
  implementation.
- Measure: =run-perf-comparison= on a large =releasegroup-releases= page and
  the =artist-releasegroups= baseline, main vs branch in one session, ratios
  only. Watch render, filter-keystroke and sort time with the C1 layout
  expanded on many rows.

*** DONE P0 — explain the =data-li-big-src= size mismatch (F0)
In the snapshot, =data-li-big-src= has the =-500.jpg= size and a =//= prefix for
Born Again, Berlin ’96, Old Habits and I Am the Real Bob Dylan. For Berlin Night
it has =-250.jpg= and =https:=. =sa_caa_big_img_size= defaults to 250, so one
of the two is unexpected. =_artBuildImageLi= picks =thumbnails[bigSize]= → 1200 →
large → 500; the protocol difference suggests two archive-JSON generations, or
two cache tiers (IDB record vs fresh fetch), feeding it.
- Probe (new, to write in P0): =scripts/probe-caa-thumbnail-keys.py= — fetch the five releases' JSON
  and record which =thumbnails= keys and URL schemes each returns.
- Check what =sa_caa_big_img_size= was on the machine that saved the snapshot,
  and whether IDB records keep the URLs of an older setting.
- Record the result in =DEBUG-NOTES.md= before building the viewer on that
  attribute. The viewer itself should derive sizes from =imagesCache= rather
  than trusting the stamped attribute.
